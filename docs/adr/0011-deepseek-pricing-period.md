# 0011 — DeepSeek 峰谷计价的菜单栏 / 菜单标记

在不增加抓取请求、不改变 `BalanceResult` 的前提下，让 DeepSeek 的余额行与菜单栏能看出来「现在是高峰还是低谷」。规则来自 DeepSeek 官方定价页，**完全在本地时钟上推断**，与 provider 抓取、凭据、解码都无关。

## Status

已采纳（Accepted）。不改变 [0002](0002-credentials-from-config-toml.md) 的凭据边界与 [0005](0005-menubar-provider-is-explicit.md) 的「显式选择、失败不自动切换」；只对 `DeepSeek` 生效，不影响 `Kimi` / 休眠的 `OpenCode Go`。

## Context

- DeepSeek 自 2026-08-23 起按峰谷计价：峰时 = 工作日（周一至周五）北京时间 `09:00–12:00`、`14:00–18:00`；其余全部为低谷，**包括 `12:00–14:00`、周末全天与中国法定节假日全天**；峰时单价为低谷的 2 倍。
- 用户希望在下拉菜单直接看到状态，同时菜单栏也要有信号，但菜单栏空间极窄，展示倒计时 / 时刻会把标题拉得很长。
- 峰谷是「本地时钟 + 固定规则」的推断：不联网、不依赖 provider 响应，因此天然可以与余额抓取失败 / 陈旧解耦。
- 唯一的长期维护面是法定节假日：官方规则按「中国法定节假日」豁免，必须有一份放假日期表；表外年份不能猜。

## Considered Options

1. **不做标记**（否决）：用户明确要求区分峰谷。
2. **菜单栏显示倒计时（`谷 1h12m`）**（否决）：一个数字加单位就让标题变长；而且菜单栏只在 tick 时重绘，倒计时要么滞后、要么得常驻 1Hz 定时器。
3. **只用颜色区分（低谷转绿）**（否决）：零宽度，但依赖明暗 / 彩色壁纸下的对比度，色觉障碍用户读不到；本 app 已有的颜色语义（咖啡 = 守护）也会被稀释。
4. **只标高峰、低谷留空**（否决）：跨越 `09:00` / `18:00` 时菜单栏项宽度会跳，旁边图标跟着位移；而且「没标记」同时代表低谷、表未覆盖、抓取失败三种状态。
5. **把峰谷塞进 `BalanceResult`**（否决）：把「本地时钟推断」混进「provider 抓取结果」，陈旧值语义会被污染。
6. **内置节假日表 + 恒定单字形对 + presenter 直调纯函数**（选定）。

## Decision

- 新增 `Balance/DeepSeekPricing.swift`：纯函数 `period(at:)`（`.peak` / `.offPeak` / `.unknown`）、`nextTransition(after:)`、文案与字形表；时区**固定 `Asia/Shanghai`**，不跟随本机时区（计费按 UTC 定义，北京 = UTC+8 无夏令时）。
- 峰时窗口左闭右开：`[09:00, 12:00)` 与 `[14:00, 18:00)`；周末（周六 / 周日）与节假日表命中的日期一律低谷，周末判定独立于节假日表，因此调休上班的周六 / 周日仍算低谷。
- 节假日表内置 2026、2027 的**放假日期**（国办发明电〔2025〕7 号、〔2026〕10 号）；调休上班日不入表。表外年份返回 `.unknown`，界面显式说明「计费时段未知（节假日表未覆盖 YYYY）」，绝不猜。
- 菜单栏在金额右侧追加**恒定一个字形**：` 峰` / ` 谷`（`.unknown`、失败、`configMissing` 一律不挂；与既有 ` ☕` 并存时字形在前）。恒定宽度避免切换点抖动。
- 下拉菜单的 DeepSeek 余额行追加 ` · 高峰 · 12:00 转低谷` / ` · 低谷 · 半价 · 明日 09:00 转高峰` / ` · 计费时段未知（…）`。切换点用**绝对时钟**（同日 `HH:mm`、次日 `明日 HH:mm`、更远 `周X HH:mm`），因为菜单只在打开时重建，倒计时会立刻过期。`⚠`（`is_available: false`）保持在金额紧随其后、峰谷说明之前。
- `renderTitle(_:now:)` / `renderMenu(_:now:)` 由 presenter 直接调用该纯函数（presenter 已知道 provider 展示名，此处只多一个 `pid == .deepseek` 分支），峰谷不进 `BalanceResult`、不进 `Inputs`，菜单打开时永远是最新时刻。
- `StatusBarController` 按下一个切换点挂**一次性定时器**，到点只重绘标题（不发请求），随后重排下一个；覆盖 30 / 60 / 120s 三档刷新间隔下最多 2 分钟的边界滞后。
- 文案用「高峰 / 低谷」而不是「空闲」，与字形 `峰` / `谷` 一一对应；「半价」只出现在低谷。

## Consequences

- 新增一个年度维护面：每年 11 月前后国务院公布次年安排后补表并发版；漏补的年份会显示「计费时段未知」，而不是错误地把假期算成高峰。
- DeepSeek 改价 / 改时段需要发版，规则写死在源码里（与「不引入远程配置」的既有取向一致）。
- 峰谷与余额抓取彻底解耦：抓取失败但有旧值时字形照常显示（峰谷是本地时钟推断，不是旧数据）；无值 / 配置缺失时不挂字形，避免与 `⚠︎` 抢语义。
- `SelfCheck` 全部渲染断言改为显式传入固定时刻（`shanghai(...)` 辅助函数），否则断言会随墙上时钟在 `峰` / `谷` 之间翻转。
- 若恢复 `OpenCode Go` 或新增其它 provider，峰谷逻辑不受影响：`ProviderID.supported` 里只有 `.deepseek` 走该分支。
