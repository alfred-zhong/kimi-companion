App.swift（入口与依赖装配）

这是整个 app 唯一的组合根：进程启动后在这里创建所有对象，并把它们按构造器注入的方式串起来。它不包含任何业务逻辑，只决定「谁依赖谁」，因此也是理解其余四个文件关系的最佳起点。

两个系统框架，零第三方依赖

这两行把 AppKit 与 Foundation 引入编译单元：前者提供 NSApplication、NSMenu 等桌面应用基础设施，后者提供 URL、Data、FileManager 这类基础类型。整个文件没有引入任何第三方包，这直接决定了 app 的启动路径足够短，也解释了为什么它能在只装 Command Line Tools 的机器上构建。

值得留意的是，这个入口文件本身并不实现业务，它甚至没有引用项目内的其他模块。真正的抓取、聚合、渲染都藏在后续构造出来的对象里，入口只负责把参数递进去。这种「薄入口 + 厚对象」的结构让启动流程可以逐行读成一张装配清单，而不会有隐藏的静态初始化。

先判断模式，再决定要不要创建 GUI

@main 标注在一个 enum 上，提供了一个自定义的 static func main()，因此 Swift 不再生成默认的入口，而是调用这里。函数做的第一件事是检查命令行参数里有没有 --self-check：有就直接执行 SelfCheck.run() 并用它的返回值作为退出码，整个图形界面根本不会被创建。这是这个项目唯一的测试入口，也让 make test 可以在无窗口环境下跑完所有断言。

没有该参数时，代码创建 AppDelegate，拿到 NSApplication.shared，然后调用 setActivationPolicy(.accessory)。这一步是菜单栏工具的关键：它让进程以辅助应用形态运行，没有 Dock 图标，也不会出现在 Cmd+Tab 切换器里，但依然可以拥有状态栏项和普通窗口。随后设置 delegate、进入 app.run() 的主事件循环。

这里还有一个容易忽略的细节：NSApplication.shared 必须在任何 UI 对象创建之前取到，而 delegate 的强引用由 app.delegate 持有，所以 delegate 局部变量在函数返回后不会被立刻释放。整段代码只有十几行，却把「测试模式」和「GUI 模式」两条完全不同的生命周期清晰地分开了。

唯一的组合根

AppDelegate 是整个 app 的依赖注入装配点。它在 applicationDidFinishLaunching 里按顺序创建：配置读取器、设置存储、日志读取器、两个数据源、刷新控制器、休眠守卫、偏好窗口控制器，最后是状态栏控制器。所有依赖都通过构造器参数传入，没有任何单例或全局查找表，因此每个对象的依赖在创建处就能读出来。

第一步 installMainMenu() 与业务无关，但必不可少：accessory 应用没有默认主菜单，如果不装一个最小菜单，偏好窗口里的 Cmd+C / Cmd+V 会完全失效。随后用 NSHomeDirectory() 拼出 kimi-code 的数据根目录，再交给 SessionCleanup.dataHome 统一派生——这是全 app 唯一的路径拼接点，清理器与会话日志读取都从它出发。

config.toml 只在启动时读一次，用途也只有一个：从 default_model 前缀推导菜单栏首选的 provider。之后真正的刷新会自己再读配置，所以这里读失败也不会阻塞启动。SettingsStore 拿这个推导值作为初始 fallback，但用户一旦显式选择过，就由 UserDefaults 里的值优先。

接下来的装配顺序值得注意。WireLogReader 的根目录是 <kimi-code home>/sessions；LiveBalanceSource 复用同一个 configSource；两个 Source 被塞进 RefreshController，后者持有 AppState 并按 settings.intervalSeconds 设定刷新周期。SleepGuard 与 SettingsWindowController 相对独立，前者只依赖 state，后者只接收一个「间隔变更」回调。

最后构造的是 StatusBarController，它拿到的参数最多：刷新控制器、状态、休眠守卫，以及三个闭包。onShowSettings 与 onSelectProvider 都用 weak 捕获，避免状态栏控制器反过来强引用设置对象形成环；currentPolicy 则刻意不在启动时求值，而是每次点击清理时现取，这样偏好面板改了保留策略立即生效。

整个方法结束后，statusBar 被强引用在 delegate 上，其余对象由各自的持有者链式引用，生命周期与 app 一致。applicationWillTerminate 里只做一件事：取消休眠守卫，保证退出时不会残留 IOPM 断言。至于首次 tick 被触发两次（初始化一次 + timer 首次一次）是已知行为，后续 tick 有重入保护，不会重复写状态。

/// 菜单栏所需的状态：每个 provider 自己的余额状态（互不影响）+ 日用量 + 阻止休眠会话 +
/// 当前菜单栏展示的 provider。
///
/// 所有修改必须经过 setter，且 setter 都在主线程被调用（`RefreshController` 走 `MainActor.run`）。
public final class AppState: ObservableObject, @unchecked Sendable {
    /// config.toml 不可读 / 非法（全局降级 → 菜单栏 `?kimi`）。
    @Published public private(set) var configMissing: Bool = false
    /// provider → 该 provider 的余额状态。`ProviderID.supported` 全部有键。
    @Published public private(set) var balances: [ProviderID: ProviderBalanceState] = [:]
    @Published public private(set) var daily: DailyUsageSnapshot?
    @Published public private(set) var lastDailyError: String?
    @Published public private(set) var caffeinateSession: CaffeinateSession?
    /// 菜单栏展示哪个 provider 的值。用户显式选择，**失败时不自动切换**。
    @Published public private(set) var selectedProvider: ProviderID = .deepseek

    public init() {}

    /// 一次写入完整 Balance Refresh Outcome；逐 provider 的合并细节不泄漏给调用方。
    public func applyBalance(_ outcome: BalanceRefreshOutcome) {
        self.balances = outcome.balances
        self.configMissing = outcome.configMissing
    }

    public func setDaily(_ snap: DailyUsageSnapshot?) { self.daily = snap }
    public func setDailyError(_ msg: String?) { self.lastDailyError = msg }
    public func setCaffeinateSession(_ s: CaffeinateSession?) { self.caffeinateSession = s }
    public func setSelectedProvider(_ p: ProviderID) { self.selectedProvider = p }

    /// 单个 provider 的状态；尚未采集过时返回空态（result / failure 皆 nil）。
    public func balance(for provider: ProviderID) -> ProviderBalanceState {
        balances[provider] ?? ProviderBalanceState(provider: provider)
    }
}

状态只读对外，写入必须过 setter

AppState 是一个 ObservableObject，持有六个 @Published 属性：配置是否缺失、per-provider 余额字典、日用量快照、日用量错误、休眠会话、当前选中的 provider。它们全部声明为 private(set)，外部只能读不能改，所有修改都走下面命名清晰的 setter。

余额被设计成 [ProviderID: ProviderBalanceState] 而不是单个快照，是因为三个 provider 的抓取互相独立：一个失败绝不能把另一个的值冲掉。字典的键集合由 ProviderID.supported 决定，balance(for:) 在缺键时返回一个空态（result 与 failure 都是 nil），界面因此不需要处理「键不存在」这种半状态。

类被标记为 @unchecked Sendable，意味着编译器不再自动证明线程安全，而由开发者承诺「所有 setter 都在主线程调用」。这个承诺由 RefreshController 里的 await MainActor.run { ... } 履行。一旦有人在后台线程直接调 setter，@Published 的通知就可能与界面读取竞争，因此这个约束值得在 review 时盯住。

applyBalance 一次写入完整的 BalanceRefreshOutcome，把逐 provider 的合并细节留在控制器内部；调用方不需要知道某个 provider 是成功、失败还是沿用旧值。这种「整体替换」也天然避免了写一半的状态被界面读到。

/// 定时刷新编排：每次 tick 从两个 Source 抓快照，根据采集事实落 `AppState`。
/// 抓取细节（config / creds / http / reader / aggregate）由 Source 实现封进。
public final class RefreshController: @unchecked Sendable {
    public let balanceSource: BalanceSource
    public let dailySource: DailyUsageSource
    public let state: AppState
    public var intervalSeconds: TimeInterval

    public init(
        balanceSource: BalanceSource,
        dailySource: DailyUsageSource,
        state: AppState,
        intervalSeconds: TimeInterval = 60
    ) {
        self.balanceSource = balanceSource
        self.dailySource = dailySource
        self.state = state
        self.intervalSeconds = intervalSeconds
    }

    public func tick() async {
        let now = Date()
        let balanceCapture = await balanceSource.capture(now: now)
        let dailyCapture = await dailySource.capture(now: now)
        await MainActor.run {
            self.state.applyBalance(self.balanceOutcome(for: balanceCapture))
            self.applyDaily(snap: dailyCapture.0, err: dailyCapture.1)
        }
    }

    public func refreshBalance() async {
        let capture = await balanceSource.capture(now: Date())
        await MainActor.run {
            self.state.applyBalance(self.balanceOutcome(for: capture))
        }
    }

    public func refreshDaily() async {
        let (snap, err) = await dailySource.capture(now: Date())
        await MainActor.run {
            self.applyDaily(snap: snap, err: err)
        }
    }

    /// 用户从菜单显式选择菜单栏 provider。
    @MainActor
    public func selectProvider(_ provider: ProviderID) {
        state.setSelectedProvider(provider)
    }

    /// 逐 provider 推进状态：一个 provider 的失败绝不触碰另一个，
    /// 也绝不改变 `selectedProvider`（网络抖动不能覆盖用户的显式选择）。
    private func balanceOutcome(for capture: BalanceCapture) -> BalanceRefreshOutcome {
        var merged: [ProviderID: ProviderBalanceState] = [:]
        for pid in ProviderID.supported {
            merged[pid] = ProviderBalanceState.advanced(
                provider: pid,
                previous: state.balances[pid],
                incoming: capture.capture(for: pid),
                now: capture.capturedAt
            )
        }
        return BalanceRefreshOutcome(
            balances: merged,
            configMissing: capture.configMissing,
            defaultModel: capture.defaultModel
        )
    }

    private func applyDaily(snap: DailyUsageSnapshot?, err: SnapshotError?) {
        self.state.setDaily(snap)
        if let err {
            self.state.setDailyError(err.menuText)
        } else {
            self.state.setDailyError(nil)
        }
    }
}

两个 Source、一次主线程提交

RefreshController 的接口很小：tick() 做完整刷新，refreshBalance() 与 refreshDaily() 分别供菜单里的单项刷新使用，selectProvider(_:) 处理用户的显式选择。intervalSeconds 是唯一可变属性，偏好面板改动刷新间隔时直接赋值，下一次 timer 重建时生效。

tick() 先取一个统一的 now，然后依次 await balanceSource.capture(now:) 和 await dailySource.capture(now:)。两个抓取是串行的，而不是 async let 并发：这样实现简单，也保证同一轮里余额与用量看到的是同一个时间基准；代价是慢的余额请求会推迟用量刷新，在当前 10 秒超时下可以接受。

拿到两份结果后，代码用 await MainActor.run 一次性切回主线程，把余额合并结果和用量结果写进 state。把两次写入收在同一个主线程块里，界面只会看到一轮完整的新状态，而不会先看到新余额、再看到旧用量。

balanceOutcome(for:) 是合并策略的核心：它遍历 ProviderID.supported，对每个 provider 调用 ProviderBalanceState.advanced(provider:previous:incoming:now:)，由后者决定是采用新值、保留旧值并标 stale、还是记录 failure。控制器自己不判断成功失败，只负责把「上次的值」和「这次的结果」配对传进去。

注意这里完全没有触碰 selectedProvider：某次抓取失败不会自动把菜单栏切到另一个 provider，用户的选择始终优先。applyDaily 则把 SnapshotError? 翻译成 lastDailyError 的文案，成功时显式清空错误，避免上一次的错误残留。

Providers.swift（三个余额 provider）

一个很小的协议加三个各自独立的实现：DeepSeek 查账户余额、OpenCode Go 查三段配额、Kimi 查 Moonshot 余额。三个实现刻意保留各自的「怪癖」（字符串数字、尾斜杠 401、OpenAI 兼容路径、只读 services 段），并把失败统一收敛成 HTTPError。

import Foundation

public protocol BalanceProvider: Sendable {
    var id: ProviderID { get }
    /// 校验该 provider 是否有可用的鉴权凭据。
    func hasCredential(creds: any CredentialSource) -> Bool
    /// 拉取余额 / 配额。
    func fetch(creds: any CredentialSource, http: HTTPClient) async throws -> BalanceResult
}

两个方法定义一个 provider

BalanceProvider 只有两个要求：hasCredential(creds:) 做凭据预检，fetch(creds:http:) 真正发起请求并返回 BalanceResult。凭据读取被抽象成 CredentialSource，HTTP 被抽象成 HTTPClient，因此实现里看不到 FileManager 与 URLSession，测试可以完整替换这两条边界。

协议继承 Sendable，因为 provider 实例会被 LiveBalanceSource 在后台任务里持有和调用。三个实现都是 struct 且字段只有 id 与可选的 baseURL，天然满足值语义。新增 provider 只需要多一个 case、一个 struct，以及在注册表的开关里补一行——漏掉的话编译器会在穷尽 switch 上报错。

/// 规范化 config.toml 的 `base_url`：去首尾空白、去尾部 `/`，并强制 HTTPS。
/// 不合格（空 / 非 https / 无 host）→ 回退到 `fallback`。
///
/// 去尾斜杠不只是洁癖：OpenCode Go 的 `…/v1/usage/`（带尾斜杠）会返回 **401**，
/// 而 `…/v1/usage` 才是 200。
func normalizeBaseURL(_ raw: String?, fallback: String) -> String {
    var s = (raw ?? "").trimmingCharacters(in: .whitespacesAndNewlines)
    while s.hasSuffix("/") { s.removeLast() }
    guard let url = URL(string: s), url.scheme == "https", let host = url.host, !host.isEmpty else {
        return fallback
    }
    return s
}

一个看似洁癖、实则救命的规范化

函数先把配置里的 base_url 去掉首尾空白，再用 while 循环剥掉所有尾部斜杠——用循环而不是一次 removeLast，是为了容忍用户写成 https://host/v1/// 这种形态。随后用 URL 解析并检查 scheme 必须是 https、host 不能为空，任何一项不满足就整体回退到官方默认地址。

注释里点明了去尾斜杠的真实原因：OpenCode Go 的配额接口对 …/v1/usage/ 返回 401，对 …/v1/usage 返回 200。这不是风格问题，而是服务端路由的硬性差异。

强制 HTTPS 则是一条安全边界：配置里写 http:// 的地址不会把 Bearer token 明文发出去，而是静默回退到官方 HTTPS 端点。回退策略的取舍是「宁可查错地址也不泄露凭据」，对只服务三个固定 provider 的 app 来说风险可控。

// MARK: - DeepSeek

/// DeepSeek（`api.deepseek.com`）账户余额 provider：
/// `GET <base_url>/user/balance`，`Authorization: Bearer <api_key>`。
///
/// 响应形状：
/// ```json
/// {"is_available":true,"balance_infos":[{"currency":"CNY","total_balance":"65.92",
///   "granted_balance":"0.00","topped_up_balance":"65.92"}]}
/// ```
/// - `total_balance` 是**字符串**（`"65.92"`）而非数字，必须 `Double(String)`；
/// - `is_available` 是真 bool；false 时金额仍然是真数据，但展示层会追加 ` ⚠`；
/// - 401 的 body 是纯文本 `Authentication Fails (governor)`，由 `HTTPClient` 统一转成 `.unauthorized`。
public struct DeepSeekProvider: BalanceProvider {
    public let id: ProviderID = .deepseek
    /// config.toml 的 `base_url`；nil / 空 / 不合格 → 官方默认。
    public let baseURL: String?

    public init(baseURL: String? = nil) {
        self.baseURL = baseURL
    }

    public static let defaultBaseURL = "https://api.deepseek.com"

    /// `<base_url>/user/balance`。
    public static func balanceURL(baseURL: String?) -> URL {
        URL(string: normalizeBaseURL(baseURL, fallback: defaultBaseURL) + "/user/balance")!
    }

    public func hasCredential(creds: any CredentialSource) -> Bool {
        creds.resolve(id.configSectionName) != nil
    }

    public func fetch(creds: any CredentialSource, http: HTTPClient) async throws -> BalanceResult {
        guard let key = creds.resolve(id.configSectionName) else {
            throw HTTPError.missingCredential
        }
        let (data, _) = try await http.get(
            url: Self.balanceURL(baseURL: baseURL),
            headers: ["Authorization": "Bearer \(key)"],
            timeoutSeconds: 10
        )
        return try Self.decode(data)
    }

    /// 解码响应。`balance_infos` 缺失 / 为空 / `total_balance` 不可解析 → `invalidResponse`
    /// （宁可报错，也不展示一个凭空的 `¥0.00`）。
    public static func decode(_ data: Data) throws -> BalanceResult {
        guard let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
              let infos = json["balance_infos"] as? [[String: Any]],
              let first = infos.first,
              let total = jsonDouble(first["total_balance"]),
              total.isFinite
        else {
            throw HTTPError.invalidResponse
        }
        let currency = (first["currency"] as? String) ?? "CNY"
        return BalanceResult(
            provider: .deepseek,
            balance: total,
            currency: currency.uppercased() == "CNY" ? .cny : .usd,
            isAvailable: json["is_available"] as? Bool
        )
    }
}

结构简单，解析挑剔

DeepSeekProvider 保存一个可选的 baseURL，默认值是 https://api.deepseek.com。balanceURL 先走 normalizeBaseURL，再拼上 /user/balance，因此无论是用户配置还是官方默认，最终 URL 都经过同一套校验。凭据取自 config.toml 的 [providers.DeepSeek] 段（段名来自 id.configSectionName）。

fetch 里先 guard let key，没有凭据直接抛 .missingCredential，不会发出一个注定 401 的请求。请求头是标准的 Authorization: Bearer <key>，超时写死 10 秒——菜单栏应用不能因为一个慢接口把整轮刷新拖住。

解码采用全有或全无策略：响应必须是对象，balance_infos 必须是非空数组，第一个元素的 total_balance 必须能解析成有限数字，否则统一抛 .invalidResponse。代码宁可让菜单显示「响应解析失败」，也不展示一个凭空的 ¥0.00——后者会让用户以为余额真的花光了。

币种字段缺失时默认按 CNY 处理，只有明确不是 CNY 时才落到 .usd。is_available 被原样保留成可选 Bool：false 时金额仍然是真数据，展示层会在余额行追加 ⚠，而不是把数字抹掉。注意 401 的响应体是纯文本 Authentication Fails (governor)，它不会进到这里，而是由 URLSessionHTTPClient 在非 2xx 时提前分类成 .unauthorized(401)。

/// JSON 数值兼容取法：线上既可能是字符串（DeepSeek 的 `total_balance` 就是 `"65.92"`）
/// 也可能是数字（Moonshot 的 `available_balance`）。两者都接受，其余返回 nil。
func jsonDouble(_ v: Any?) -> Double? {
    if let s = v as? String { return Double(s) }
    if let n = v as? NSNumber { return n.doubleValue }
    return nil
}

同一个字段，两种线上形状

JSONSerialization 会把 JSON 数字解析成 NSNumber，而字符串仍然是 String。线上三个接口对金额的写法并不统一：DeepSeek 的 total_balance 是字符串 "65.92"，Moonshot 的 available_balance 是数字 49.58894。这个函数把两种形状都收敛成 Double?。

顺序上先判断 String 再判断 NSNumber，其他类型（数组、字典、null、Bool 以外的对象）一律返回 nil，交给调用方的 guard 去报 .invalidResponse。它不抛错、不做范围检查，只负责「能不能变成数字」这一个问题，这样各 provider 的解码条件可以保持可读。

// MARK: - OpenCode Go

/// OpenCode Go（`opencode.ai/zen/go` 订阅网关）配额 provider：
/// `GET <usage_base_url>/usage`，`Authorization: Bearer <api_key>`。
///
/// 响应形状：
/// ```json
/// {"usage":{"rolling":{"status":"ok","percent":16,"resetsAt":"2026-09-22T11:17:56.356Z"},
///           "weekly":{"status":"ok","percent":22,"resetsAt":"..."},
///           "monthly":{"status":"ok","percent":13,"resetsAt":"..."}}}
/// ```
/// 四条实测坑：
/// 1. **尾部 `/` 会 401**（`…/v1/usage` → 200，`…/v1/usage/` → 401 `AuthError`），
///    故 base_url 先去掉尾斜杠再拼 `/usage`（`normalizeBaseURL`）。
/// 2. **`x-opencode-session` 头不需要**：带与不带该头的响应逐字节一致，
///    且响应声明的 `access-control-allow-headers` 里根本没有它 —— 因此不解析 `custom_headers`。
/// 3. `percent` 是 JSON 数字、含义是**已用**百分比（0-100）；`status` 原样保留，
///    `!= "ok"` 一律按已限流处理（菜单里进度条转红并带出原始状态串）。
/// 4. kimi-code 里 `base_url` 配的是 **OpenAI 兼容地址**
///    （`https://opencode.ai/inference/go/openai/v1`，客户端再拼 `/chat/completions`），
///    而配额接口挂在产品路径下：`…/inference/go/openai/v1/usage` → **404**，
///    `…/inference/go/v1/usage` → 200。两者只差一个 `openai` 路径段，
///    故拼 `/usage` 前先摘掉该段（`usageBaseURL`）；老写法 `…/zen/go/v1` 没有这一段，原样使用。
///
/// 三窗口 all-or-nothing：任一窗口缺失 / malformed → `invalidResponse`，不返回半截报告。
public struct OpenCodeGoProvider: BalanceProvider {
    public let id: ProviderID = .opencodeGo
    public let baseURL: String?

    public init(baseURL: String? = nil) {
        self.baseURL = baseURL
    }

    public static let defaultBaseURL = "https://opencode.ai/zen/go/v1"

    /// `/usage` 所在的 base：去尾斜杠，并摘掉 OpenAI 兼容地址里的 `openai` 路径段。
    /// 例：`https://opencode.ai/inference/go/openai/v1` → `https://opencode.ai/inference/go/v1`；
    /// `https://opencode.ai/zen/go/v1` 原样返回。
    public static func usageBaseURL(_ raw: String?) -> String {
        let base = normalizeBaseURL(raw, fallback: defaultBaseURL)
        guard var components = URLComponents(string: base) else { return base }
        var segments = components.path.split(separator: "/", omittingEmptySubsequences: true).map(String.init)
        guard let index = segments.firstIndex(where: { $0.lowercased() == "openai" }) else { return base }
        segments.remove(at: index)
        components.path = "/" + segments.joined(separator: "/")
        return components.url?.absoluteString ?? base
    }

    /// `<usageBaseURL>/usage`。
    public static func usageURL(baseURL: String?) -> URL {
        URL(string: usageBaseURL(baseURL) + "/usage")!
    }

    public func hasCredential(creds: any CredentialSource) -> Bool {
        creds.resolve(id.configSectionName) != nil
    }

    public func fetch(creds: any CredentialSource, http: HTTPClient) async throws -> BalanceResult {
        guard let key = creds.resolve(id.configSectionName) else {
            throw HTTPError.missingCredential
        }
        let (data, _) = try await http.get(
            url: Self.usageURL(baseURL: baseURL),
            headers: ["Authorization": "Bearer \(key)"],
            timeoutSeconds: 10
        )
        return try Self.decode(data)
    }

    /// 窗口描述表：响应键 → (id, 展示标签)。顺序即菜单里的展示顺序。
    static let windowDescriptors: [(key: String, id: String, label: String)] = [
        ("rolling", "5h", "5h"),
        ("weekly", "7d", "7d"),
        ("monthly", "monthly", "月度"),
    ]

    public static func decode(_ data: Data) throws -> BalanceResult {
        guard let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
              let usage = json["usage"] as? [String: Any]
        else {
            throw HTTPError.invalidResponse
        }
        let windows = try decodeWindows(usage)
        // 状态栏主窗口取 rolling（5h）。
        guard let rolling = windows.first(where: { $0.id == "5h" }) else {
            throw HTTPError.invalidResponse
        }
        return BalanceResult(
            provider: .opencodeGo,
            balance: rolling.usedPercent,
            currency: .percent,
            usedPercent: rolling.usedPercent,
            resetRemaining: max(0, rolling.resetsAt.timeIntervalSince(Date())),
            quotaWindows: windows
        )
    }

    static func decodeWindows(_ usage: [String: Any]) throws -> [QuotaWindow] {
        var out: [QuotaWindow] = []
        out.reserveCapacity(windowDescriptors.count)
        for descriptor in windowDescriptors {
            guard let raw = usage[descriptor.key] as? [String: Any],
                  let percentNumber = raw["percent"] as? NSNumber,
                  let status = raw["status"] as? String,
                  let resetsAtRaw = raw["resetsAt"] as? String,
                  let resetsAt = parseISO(resetsAtRaw)
            else {
                throw HTTPError.invalidResponse
            }
            let percent = percentNumber.doubleValue
            guard percent.isFinite, percent >= 0, percent <= 100 else {
                throw HTTPError.invalidResponse
            }
            out.append(QuotaWindow(
                id: descriptor.id,
                label: descriptor.label,
                usedPercent: percent,
                status: status,
                resetsAt: resetsAt
            ))
        }
        return out
    }

    /// ISO 时间戳解析：默认格式先试（`…T12:00:00Z`），失败再试带小数秒
    /// （live 响应形状 `…T13:02:42.270Z`，`ISO8601DateFormatter` 默认解析不了）。
    static func parseISO(_ s: String) -> Date? {
        if let d = ISO8601DateFormatter().date(from: s) { return d }
        let f = ISO8601DateFormatter()
        f.formatOptions = [.withInternetDateTime, .withFractionalSeconds]
        return f.date(from: s)
    }
}

一个 provider，四条实测坑

OpenCode Go 返回的是三段配额窗口：rolling（5 小时）、weekly（7 天）、monthly（月度），每段带 percent（已用百分比）、status 和 resetsAt。默认 base 是 https://opencode.ai/zen/go/v1，配额接口挂在该路径下的 /usage。

真正麻烦的是地址形态。kimi-code 里配置的 OpenAI 兼容地址 是 https://opencode.ai/inference/go/openai/v1，客户端会在后面拼 /chat/completions；而配额接口挂在产品路径 …/inference/go/v1/usage 下，两者只差一个 openai 路径段。因此 usageBaseURL 先规范化，再按路径段拆分、找到 openai 并移除，最后重组 URL。老写法 …/zen/go/v1 没有这一段，原样返回。

decode 先取 usage 对象，再要求 decodeWindows 返回完整三段。窗口描述表把响应键映射成展示顺序与标签（5h / 7d / 月度），顺序即菜单顺序。任一窗口缺失、percent 不是数字、超出 0…100、status 或 resetsAt 缺失，都会抛出 .invalidResponse——这是又一次全有或全无，不允许返回半截报告。

时间解析有两级回退：先试 ISO8601DateFormatter 的默认ISO 8601格式，失败再打开 .withFractionalSeconds。live 响应里的 …T13:02:42.270Z 属于后者，默认解析器会返回 nil，这正是二级回退存在的理由。

组装结果时，状态栏主值取 rolling 的已用百分比，resetRemaining 用 max(0, resetsAt - now) 保证不会出现负数倒计时。status 原样保留在 QuotaWindow 里：只要不是 "ok"，展示层就会把进度条强制转红，并把服务端原始状态串带在行内，否则用户只能看到一个无法解释的红条。

/// Kimi / Moonshot 开放平台余额 provider：
/// `GET https://api.moonshot.cn/v1/users/me/balance`，`Authorization: Bearer <api_key>`。
///
/// 响应形状（国内站 / 国际站同构，单位由站点隐含）：
/// ```json
/// {"code":0,"data":{"available_balance":49.58894,"voucher_balance":46.58893,
///   "cash_balance":3.00001},"scode":"0x0","status":true}
/// ```
/// 与另两个 provider 的两处不同（决策见 `docs/adr/0008-kimi-balance-scope-and-currency.md`）：
/// 1. **地址与币种写死国内站**，不读 `base_url`：响应里**没有** currency 字段，单位只由站点
///    隐含（`api.moonshot.cn` = 人民币，`api.moonshot.ai` = 美元），本 app 只服务国内站；
///    拿国际站 key 来查的后果是一次响亮的 `鉴权失败 (401)`，不是静默错值。
/// 2. **凭据来自 kimi-code 的内置工具服务段**（`[services.moonshot_search]` /
///    `[services.moonshot_fetch]`），而不是 `[providers.*]` 段。
///
/// `available_balance` = 现金 + 代金券，就是「还能不能调用推理 API」的那个数：`≤ 0` 时推理调用
/// 返回 `exceeded_current_quota_error`，故 `isAvailable = balance > 0`（菜单里会追加 ` ⚠`）。
/// 三个余额字段 all-or-nothing：任一缺失 / 不可解析 → `invalidResponse`，
/// 宁可报错也不展示一个凭空的 `¥0.00`。
public struct KimiProvider: BalanceProvider {
    public let id: ProviderID = .kimi

    /// 余额端点：写死国内站，`base_url` 不参与（ADR-0008）。
    public static let balanceURL = URL(string: "https://api.moonshot.cn/v1/users/me/balance")!

    /// 凭据段候选，按顺序取第一个存在的；两段通常指向同一把平台 key。
    /// 用「凭据路径」写法（`services.<段名>`），与 `KimiConfig.credentialSection(_:)` 对齐。
    public static let credentialSectionNames = [
        "services.moonshot_search",
        "services.moonshot_fetch",
    ]

    public init() {}

    /// 凭据预检：段缺失 / `api_key` 为空 / 只写了 `api_key_env` 各给一条可照抄的中文说明，
    /// 可用时返回 nil。文案在这里拼 —— 只有它知道候选段名，`ProviderFailure` 不需要知道。
    public static func credentialPreflight(_ cfg: KimiConfig) -> ProviderFailure? {
        let present = presentCredentialSections(cfg)
        guard let first = present.first else {
            let names = credentialSectionNames.joined(separator: " 或 ")
            return .credentialSection("config 中未找到 \(names) 的 api_key")
        }

/// kimi-code 会话记录增量读取：`sessions/<workspace>/<session>/agents/<agent>/wire.jsonl`。
///
/// **契约**：`events(now:)` 返回「保留窗口内的 usage 事件集合」，等价于
/// 「按当前文件系统状态完整重扫一遍得到的同一集合」。
/// 保留窗口 = `tsMs >= min(当日零点, now − 12h)`，与 mtime 剪枝边界同值。
///
/// **实现**：进程内持有每个文件的 Read Cursor（已消费偏移 + 指纹 + 未成行的尾部字节），
/// 每次调用只读取自上次以来被追加的字节；窗口内事件与去重键随 `now` 前进淘汰。不落盘。
///
/// **为什么必须遍历全部 `agents/*/wire.jsonl`**：每个 agent 的文件完全独立、跨文件零重复
/// （实测 600 条记录 600 个不同签名，0 条出现在多个文件里）。只读 `main` 会严重漏计
/// （实测某 session 的 output：main 48k，全部 agent 合计 123k）。
///
/// 同步阻塞 I/O：调用方保证不在主线程上直接调用。
/// 线程安全：整个 `events(now:)` 由内部 `NSLock` 串行化 —— 60s timer tick 与菜单「立即刷新」
/// 可能产生两个重叠的 `Task`。
public final class WireLogReader: @unchecked Sendable {
    public let sessionsRoot: String
    public let parser: WireLineParser

    private let lock = NSLock()
    /// 每文件读取状态，键为相对 sessions 根的 POSIX 路径。
    private var cursors: [String: FileCursor] = [:]
    /// 保留窗口内的事件（插入序；`retainedHead` 之前的部分已淘汰、等待压缩）。
    private var retained: [UsageEvent] = []
    private var retainedHead = 0
    /// `retained` 内事件去重键的索引。文件失效重读时防止同一事件被重复计入。
    private var seenKeys: Set<String> = []
    /// 上一次的窗口边界；用于识别时钟回拨。
    private var lastBoundaryMs: Int64?

    public init(sessionsRoot: String, parser: WireLineParser = WireLineParser()) {
        self.sessionsRoot = sessionsRoot
        self.parser = parser
    }

    /// 本机时区当日零点（ms）。
    public func todayStartMs(now: Date) -> Int64 {
        var cal = Calendar(identifier: .gregorian)
        cal.timeZone = TimeZone.current
        let comps = cal.dateComponents([.year, .month, .day], from: now)
        let startOfDay = cal.date(from: comps) ?? now
        return Int64(startOfDay.timeIntervalSince1970 * 1000)
    }

    /// 保留窗口下界（ms）= `min(当日零点, now − 12h)`；同时是 mtime 剪枝边界。
    public func boundaryMs(now: Date) -> Int64 {
        let nowMs = Int64(now.timeIntervalSince1970 * 1000)
        return min(todayStartMs(now: now), nowMs - Int64(HOUR_BUCKET_COUNT) * HOUR_MS)
    }

    /// 推进所有游标，返回保留窗口内的事件。返回顺序未定义。
    public func events(now: Date = Date()) -> [UsageEvent] {
        lock.lock()
        defer { lock.unlock() }

        let fm = FileManager.default
        guard fm.fileExists(atPath: sessionsRoot) else {
            resetAll()
            return []
        }

        let boundary = boundaryMs(now: now)
        // 淘汰的正确性依赖边界单调不减；倒退说明时钟被改过，游标与窗口都不可信 → 全量重来一次。
        if let last = lastBoundaryMs, boundary < last {
            resetAll()
        }
        lastBoundaryMs = boundary

        var touched: Set<String> = []
        collect(dir: sessionsRoot, relPath: "", boundaryMs: boundary, touched: &touched)

        // walk 没见到的文件：已删除，或 mtime 已滑出剪枝边界（后者的事件必然也已滑出窗口）。
        let stale = cursors.keys.filter { !touched.contains($0) }
        for key in stale {
            cursors.removeValue(forKey: key)
            purgeRetained(path: key)
        }

        evict(below: boundary)
        return Array(retained[retainedHead...])
    }

契约先行：等价于全量重扫

文件开头的文档注释给出了硬契约：events(now:) 返回「保留窗口内的 usage 事件集合」，并且这个集合必须等价于「按当前文件系统状态完整重扫一遍」得到的同一集合。保留窗口是 tsMs >= min(当日零点, now − 12h)，与后面 mtime 剪枝使用的边界完全同值——这个一致性是正确性的前提。

实现依赖几份进程内状态：cursors 记录每个文件的读取游标；retained 是窗口内事件数组，retainedHead 标记已被淘汰但尚未压缩的头部；seenKeys 是当前保留事件的去重键集合；lastBoundaryMs 用于识别时钟回拨。所有状态都不落盘，重启后从零开始重扫，因此不存在缓存过期问题。

events(now:) 一进来就上 NSLock：60 秒的 timer tick 与菜单里的「立即刷新」可能产生两个重叠的 Task，如果两个任务同时推进游标，偏移与事件数组都会错乱。锁的范围覆盖整个调用，因此这是一个彻底的串行化，而不是细粒度锁。

进入临界区后先检查 sessionsRoot 是否存在，不存在就清空全部状态并返回空数组。随后计算边界；如果新边界小于上一次的边界，说明系统时钟被往回调过，此时游标位置和窗口都不可信，代码选择 resetAll() 全量重来，而不是尝试修补。

接下来递归遍历 sessionsRoot，把本轮见到的文件放进 touched。遍历结束后，cursors 里所有没被 touch 的条目意味着文件已删除或mtime 剪枝滑出边界，于是移除游标并清掉该文件贡献的保留事件。最后 evict(below:) 按时间淘汰窗口外的事件，返回 retained[retainedHead...] 的切片。

之所以必须遍历所有 agents/*/wire.jsonl 而不只读 main，注释里给了实测依据：每个 agent 的文件完全独立、跨文件零重复（600 条记录对应 600 个不同签名），只读 main 会把 output 从 123k 漏计到 48k。这个数据也解释了为什么去重键要带相对路径——不同 agent 的行偏移可能相同。

FileCursor 是一个极小的值类型，包含已消费偏移 offset、上次看到的文件大小 size、修改时间 mtimeMs、文件身份 identity，以及尚未成行的残余字节 carry。它的核心不变量是：offset 永远停在某个完整换行符之后，因此 offset 可以直接作为下一行的字节偏移。

identity 保存的是文件系统的 inode 标识（通过 fileResourceIdentifier 取得）。路径相同不代表还是同一个文件：编辑器保存、日志轮转都可能先删后建，此时内容从头开始，旧偏移必须作废。用 inode 比较比比较大小更可靠，因为新建文件碰巧超过旧偏移时，大小检查会漏判。

carry 是半行缓冲：一次读到的最后一段可能没有换行，代码把这部分留着，等下一次追加再把两边拼起来。没有它，一个正在写入的半行会被当作完整行解析失败，然后永久跳过。

size 与 mtimeMs 是判断「文件被截断」和「原地改写」的依据：新大小小于已读位置说明被截断；大小不变而 mtime 前进说明内容被替换但没有改变长度。这两种情况都会触发清除该文件的历史事件并重置游标。

            if values.isDirectory == true {

            let mtimeMs = Int64((values.contentModificationDate?.timeIntervalSince1970 ?? 0) * 1000)

                relPath: childRel,

                mtimeMs: mtimeMs,
                identity: values.fileResourceIdentifier as? NSObject,
                boundaryMs: boundaryMs

        }

递归逻辑很直接：拿到条目后先取属性，是目录就带着新的相对路径继续递归，不是目录则只处理文件名恰好为 wire.jsonl 的项。其他文件（session 元数据、索引等）被完全忽略，既省 I/O 也避免误读。

对每个 wire 文件先算 mtimeMs，小于边界的直接 continue。这就是mtime 剪枝：文件按时间追加写入，最后修改时间早于窗口下界，意味着里面不可能有窗口内的事件，整份文件都不用打开。这个判断与 boundaryMs 完全同值，因此不会误剪。

通过剪枝的文件会被加入 touched，然后交给 processFile。注意 touched 只包含「本轮实际访问过」的文件，未出现的游标会在 events 里被当作删除处理——这要求每次调用都完整遍历整棵树，而不能只遍历上次的子集。

contentsOfDirectory 失败时函数直接返回，不抛错。目录暂时不可读（权限、竞态删除）不应该让整轮刷新失败，最多是这一轮少算一些事件，下一轮还能补回来。

            }

先判断旧游标还能不能用

processFile 拿到路径、大小、mtime、身份和边界，先取出旧游标。readPoint 定义为 offset + carry.count，即「已经读到文件里的哪个位置」。接下来依次检查三种会让旧游标失效的情况。

第一是身份变化：如果旧inode 与新 inode 不等，说明文件被替换，旧内容的全部保留事件都要清除，游标归零。第二是截断：新大小小于 readPoint，说明文件被截短，已读位置之后的内容作废。第三是原地改写：大小恰好等于 readPoint 但 mtime 前进了——追加一定会改变长度，长度不变而时间变，只可能是内容被覆盖。

三种情况都调用 purgeRetained(path:) 再重置游标。清除历史事件这一步不能省：如果只重置游标，文件重写后同样的行偏移会出现新内容，旧去重键会让新事件被误判为重复而丢弃。

确认游标可用后，更新 size、mtimeMs、identity，计算 readFrom = offset + carry.count，只有当 size > readFrom 时才真正读文件。read 返回的字节块交给 ingest 消费，最后把更新后的游标写回字典。

这里的读取上限是 size - readFrom，即 stat 时点已知的那一段；两次调用之间新追加的字节留给下一轮。这样不会出现「读到一个没有 stat 过、大小可能还在变化」的区域，边界更可控。

    /// 消费一段新读入的字节：补上未成行的 carry，按行解析，把剩下的尾部留作新的 carry。
    private func ingest(_ chunk: Data, relPath: String, cursor: inout FileCursor, boundaryMs: Int64) {
        var buffer = cursor.carry
        buffer.append(chunk)
        cursor.carry = Data()

        // 游标只推进到最后一个完整换行：写入中的半行留到下一次拼接，否则那行会被永久跳过。
        guard let lastNewline = buffer.lastIndex(of: 0x0a) else {
            cursor.carry = buffer
            return
        }
        let complete = buffer[buffer.startIndex...lastNewline]
        if lastNewline < buffer.index(before: buffer.endIndex) {
            cursor.carry = Data(buffer[buffer.index(after: lastNewline)...])
        }

        var lineStart = complete.startIndex
        for index in complete.indices where complete[index] == 0x0a {
            let lineBytes = complete.distance(from: lineStart, to: index)
            if lineBytes > 0 {
                ingestLine(
                    Data(complete[lineStart..<index]),
                    relPath: relPath,
                    lineOffset: cursor.offset,
                    boundaryMs: boundaryMs
                )
            }
            // 空行也推进游标，否则偏移会与真实行首位置错位（进而让去重键不稳定）。
            cursor.offset += UInt64(lineBytes) + 1
            lineStart = complete.index(after: index)
        }
    }

只有最后一个换行之前的内容才算“行”

ingest 先把上次留下的 carry 拼到新字节前面，得到 buffer，并先把 cursor.carry 清空。这样即使本次没有完整行，残留也只会在函数末尾重新写回一次，不会出现重复拼接。

接着找 buffer 里最后一个换行符。如果完全没有换行，说明整个 buffer 都是半行，直接存回 carry 并返回。找到之后，把从开头到该换行（含）的部分作为 complete；换行之后若还有字节，就截下来作为新的 carry。

然后遍历 complete 中的每个换行符，用「当前换行索引 − 行首索引」得到行内字节数。lineBytes > 0 时把这段字节交给 ingestLine，空行则跳过解析；但无论是否为空行，cursor.offset 都会增加 lineBytes + 1（那个 1 是换行符本身）。注释特别强调空行也必须推进偏移，否则后续行的偏移会整体错位，去重键随之变得不稳定。

这里用字节而不是字符来推进偏移，是因为去重键和 FileHandle 的 seek 都以字节为单位。UTF-8 的多字节字符不会影响换行符定位（0x0a 不会出现在多字节序列的中间），所以按字节切分是安全的。

函数结束时，offset 停在最后一个换行之后，carry 保存其后的残余，正好满足 FileCursor 的不变量。下一次读取会从这个位置继续，半行不会丢，也不会被重复解析。

四道 guard 决定一条事件去留

第一道把字节解码成 UTF-8 字符串，解码失败直接返回。日志里出现半截多字节字符时，宁可丢这一行，也不要用替换字符拼出一个错误的事件。

第二道交给 WireLineParser.parse。解析器只识别 usage.record 与 llm.request 两种行，其余行（会话元数据、工具调用等）返回 nil，在这里被静默忽略。

第三道按时间戳过滤：事件早于 boundaryMs 的丢弃。虽然文件级已经做过 mtime 剪枝，但一个文件里仍可能同时包含窗口内和窗口外的行，这一道是行级过滤。

第四道是去重键检查：seenKeys.insert(event.dedupeKey).inserted 为 false 说明这条事件已经在 retained 里。文件被截断、替换或重读时，同一行可能被再次解析，去重集合负责兜底。四道都通过后，事件才被追加到 retained。

头部指针 + 惰性压缩

evict 从 retainedHead 开始向后扫描，只要事件时间戳小于边界就推进指针，同时把对应的去重键从 seenKeys 里移除。事件按插入顺序追加，而日志文件本身是时间序的，所以窗口外的事件集中在头部，用一个指针就够了，不需要每次删除数组元素。

真正的内存回收是惰性的：当头部空洞达到 1024 条、并且至少占数组一半时，才执行 removeFirst(retainedHead) 并重置指针。这个双条件避免了频繁压缩（空洞太小时不划算），也避免数组无限增长（空洞太大时必须回收）。

seenKeys 必须与 retained 同步收缩，否则一个已经淘汰的事件键会永久留在集合里，导致同一条日志在文件重读时被误判为重复而漏计。这里逐条 remove，成本与淘汰数量成正比。

注意淘汰只按 tsMs，不按文件。retained 里混着所有文件、两种事件类型，顺序大致是时间序，但不是严格排序（不同文件的追加节奏不同）。指针只能从头开始推进，因此遇到一条尚未过期的头部事件就会停止——这依赖「头部事件最旧」这个近似成立的性质。

    /// 丢弃某个文件贡献的全部保留事件（文件被截断 / 替换 / 删除 / mtime 剪掉时）。
    private func purgeRetained(path: String) {
        if retainedHead > 0 {

            retainedHead = 0

        for event in retained {

            }
        }
        retained = kept

先压实，再前缀过滤

purgeRetained(path:) 用于「某个文件的游标失效」的场景：文件被截断、替换、删除，或因为 mtime 滑出边界而被跳过。它要保证这个文件贡献的全部保留事件都从内存里消失，否则新内容会与旧事件混在一起。

第一步先处理头部空洞：如果 retainedHead > 0，直接 removeFirst 并把指针归零。这样接下来的遍历只需要看有效区间，不会把已淘汰的事件再处理一遍。

第二步以 "\(path):" 为前缀遍历 retained：命中的事件从 seenKeys 里删除，不命中的保留到新数组。这里重建数组而不是原地删除，是为了避免多次 remove(at:) 的 O(n²) 移动。

前缀匹配依赖去重键的格式约定。path 是相对 sessions 根的 POSIX 路径，不含冒号；如果未来路径里出现冒号，前缀判断就可能误伤，因此格式变更时要同步检查这里。

函数不修改 cursors，游标的清理由调用方负责。这样的分工让 processFile 可以在重置游标的同时清事件，而 events 的 stale 分支可以先移除游标再调用它。

把 lastBoundaryMs 也清空很重要：否则下一次调用仍会拿旧边界比较，可能再次触发重置，形成每轮都全量重扫的退化。清空后第一次调用会重新建立基准。

由于所有状态都在内存里，重置不涉及任何磁盘写入，也不会影响 kimi-code 正在写入的日志。这是「无磁盘缓存」设计的直接收益：进程内状态可以随时丢弃重建。

由 currency 决定渲染形态

valueItems 先看 result.currency：.cny / .usd 走金额分支，.percent 走配额分支。金额分支生成一行「余额 ¥65.92」，如果 isAvailable == false 再追加 ⚠——金额本身仍然是真数据，不隐藏。

配额分支要求 quotaWindows 非空，然后把每个配额窗口映射成一个 MenuItemSpec.usageBar。如果窗口明细意外缺失，percentFallbackRow 会退化成一条纯文本「已用 16% · 4h17m 后重置」，保证不会出现空白 section。

windowItem 负责单个窗口的细节：用 resetsAt - now 算剩余时间，只有大于 0 才生成「… 后重置」。当 w.isOK 为 false 时，右侧说明会变成「服务端原始 status · 倒计时」，让用户知道红条不是本地算错，而是服务端确实报了异常状态。

百分比文本用 Int(usedPercent.rounded()) 取整，与进度条的填充宽度保持一致；如果不取整，可能出现条长 16.4%、文字 16% 的轻微错位。所有数值都已由 provider 解码时保证在 0…100 范围内。

这三个函数合起来覆盖了菜单里所有「数值行」的形态：金额、百分比进度条、以及进度条缺失时的纯文本回退。新增一种展示形态（例如额度上限）时，优先在这里扩展，而不是在菜单组装逻辑里插入特判。

高度的一半就是胶囊

cornerRadius(buttonHeight:) 返回 max(buttonHeight, 1) / 2。对 18pt 高的状态栏 button，结果是 9pt，正好把矩形磨成两端半圆。下限 1 是为了防止高度为 0 时出现负半径或除零类的异常。

把公式放在独立的 enum 里，而不是散落在 presenter 与控制器中，保证「胶囊半径 = 高度一半」只有一处定义。将来如果状态栏高度随系统设置变化，只需要调整传入值。

这个类型没有任何状态，也不依赖 AppKit 的视图生命周期，因此可以被 SelfCheck 直接用几个高度值断言。它是整个文件里最小的一个类型，但体现了同一套分层原则：几何计算与视图应用分离。
